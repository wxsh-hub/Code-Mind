# 缓存设计经验总结

## 背景

缓存是提升系统性能的重要手段。本文总结了在实际项目中遇到的缓存问题和解决方案。

## 缓存策略

### Cache-Aside（旁路缓存）

最常用的缓存策略，读写流程：

**读流程**：
1. 先查缓存
2. 缓存命中，直接返回
3. 缓存未命中，查数据库
4. 将数据写入缓存
5. 返回数据

**写流程**：
1. 更新数据库
2. 删除缓存

```java
public User getUserById(Long userId) {
    String key = "user:" + userId;
    
    // 1. 先查缓存
    User user = redisTemplate.opsForValue().get(key);
    if (user != null) {
        return user;
    }
    
    // 2. 缓存未命中，查数据库
    user = userMapper.selectById(userId);
    if (user != null) {
        // 3. 写入缓存
        redisTemplate.opsForValue().set(key, user, 1, TimeUnit.HOURS);
    }
    
    return user;
}

public void updateUser(User user) {
    // 1. 更新数据库
    userMapper.updateById(user);
    
    // 2. 删除缓存
    redisTemplate.delete("user:" + user.getId());
}
```

### Read-Through（读穿透）

缓存层自动从数据库加载数据，应用只与缓存交互。

### Write-Through（写穿透）

写操作同时更新缓存和数据库。

### Write-Behind（异步写入）

先写缓存，异步更新数据库。

## 常见问题

### 1. 缓存穿透

**问题描述**：查询不存在的数据，每次都穿透到数据库。

**场景**：恶意攻击、业务 bug

**解决方案**：

#### 方案一：缓存空值
```java
public User getUserById(Long userId) {
    String key = "user:" + userId;
    User user = redisTemplate.opsForValue().get(key);
    
    if (user != null) {
        // 注意：空值标记
        if (user.getId() == null) {
            return null;
        }
        return user;
    }
    
    user = userMapper.selectById(userId);
    if (user == null) {
        // 缓存空值，设置较短过期时间
        user = new User(); // 空对象
        redisTemplate.opsForValue().set(key, user, 5, TimeUnit.MINUTES);
    } else {
        redisTemplate.opsForValue().set(key, user, 1, TimeUnit.HOURS);
    }
    
    return user;
}
```

#### 方案二：布隆过滤器
```java
@Component
public class UserBloomFilter {
```

### 2. 缓存击穿

**问题描述**：热点 key 过期，大量请求同时穿透到数据库。

**场景**：秒杀、热门商品

**解决方案**：

#### 方案一：互斥锁
```java
public User getUserById(Long userId) {
    String key = "user:" + userId;
    User user = redisTemplate.opsForValue().get(key);
    
    if (user != null) {
        return user;
    }
    
    // 获取分布式锁
    String lockKey = "lock:user:" + userId;
    boolean locked = redisTemplate.opsForValue()
        .setIfAbsent(lockKey, "1", 10, TimeUnit.SECONDS);
    
    if (locked) {
        try {
            // 双重检查
            user = redisTemplate.opsForValue().get(key);
            if (user != null) {
                return user;
            }
            
            // 查数据库
            user = userMapper.selectById(userId);
            if (user != null) {
                redisTemplate.opsForValue().set(key, user, 1, TimeUnit.HOURS);
            }
        } finally {
            redisTemplate.delete(lockKey);
        }
    } else {
        // 未获取到锁，等待后重试
        Thread.sleep(50);
        return getUserById(userId);
    }
    
    return user;
}
```

#### 方案二：逻辑过期
```java
@Data
public class CacheData<T> {
    private T data;
    private Long expireTime; // 逻辑过期时间
    
    public boolean isExpired() {
        return System.currentTimeMillis() > expireTime;
    }
}

public User getUserById(Long userId) {
    String key = "user:" + userId;
    CacheData<User> cacheData = redisTemplate.opsForValue().get(key);
    
    if (cacheData == null) {
        // 缓存未命中，查数据库
        User user = userMapper.selectById(userId);
        if (user != null) {
            cacheData = new CacheData<>();
            cacheData.setData(user);
            cacheData.setExpireTime(System.currentTimeMillis() + 3600000); // 1小时后过期
            redisTemplate.opsForValue().set(key, cacheData, 2, TimeUnit.HOURS); // 实际过期时间更长
        }
        return user;
    }
    
    if (cacheData.isExpired()) {
        // 已过期，异步更新
        asyncUpdateCache(key, userId);
    }
    
    return cacheData.getData();
}

@Async
public void asyncUpdateCache(String key, Long userId) {
    // 获取锁
    String lockKey = key + ":lock";
    if (redisTemplate.opsForValue().setIfAbsent(lockKey, "1", 10, TimeUnit.SECONDS)) {
        try {
            User user = userMapper.selectById(userId);
            CacheData<User> cacheData = new CacheData<>();
            cacheData.setData(user);
            cacheData.setExpireTime(System.currentTimeMillis() + 3600000);
            redisTemplate.opsForValue().set(key, cacheData, 2, TimeUnit.HOURS);
        } finally {
            redisTemplate.delete(lockKey);
        }
    }
}
```

### 3. 缓存雪崩

**问题描述**：大量 key 同时过期，请求全部穿透到数据库。

**解决方案**：

#### 方案一：随机过期时间
```java
// 基础过期时间 + 随机偏移
long expireTime = 3600 + RandomUtils.nextLong(0, 600); // 1小时 ± 10分钟
redisTemplate.opsForValue().set(key, value, expireTime, TimeUnit.SECONDS);
```

#### 方案二：多级缓存
```java
@Component
public class MultiLevelCache {
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    private Cache<String, Object> localCache = Caffeine.newBuilder()
        .maximumSize(1000)
        .expireAfterWrite(5, TimeUnit.MINUTES)
        .build();
    
    public User getUserById(Long userId) {
        String key = "user:" + userId;
        
        // 1. 查本地缓存
        User user = (User) localCache.getIfPresent(key);
        if (user != null) {
            return user;
        }
        
        // 2. 查 Redis
        user = (User) redisTemplate.opsForValue().get(key);
        if (user != null) {
            localCache.put(key, user);
            return user;
        }
        
        // 3. 查数据库
        user = userMapper.selectById(userId);
        if (user != null) {
            redisTemplate.opsForValue().set(key, user, 1, TimeUnit.HOURS);
            localCache.put(key, user);
        }
        
        return user;
    }
}
```

## 缓存一致性

### 延迟双删

```java
public void updateUser(User user) {
    // 1. 先删除缓存
    redisTemplate.delete("user:" + user.getId());
    
    // 2. 更新数据库
    userMapper.updateById(user);
    
    // 3. 延迟再删一次（防止并发读写导致脏数据）
    CompletableFuture.runAsync(() -> {
        try {
            Thread.sleep(500); // 延迟 500ms
            redisTemplate.delete("user:" + user.getId());
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    });
}
```

### 监听 Binlog

```java
@Component
public class BinlogListener {
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @KafkaListener(topics = "binlog-user")
    public void onBinlog(BinlogEvent event) {
        if (event.getType() == EventType.UPDATE || event.getType() == EventType.DELETE) {
            Long userId = event.getData().getId();
            redisTemplate.delete("user:" + userId);
        }
    }
}
```

## 最佳实践

1. **设置合理的过期时间**：避免数据永久缓存
2. **使用缓存预热**：系统启动时加载热点数据
3. **监控缓存命中率**：及时发现缓存问题
4. **使用分布式锁**：防止缓存击穿
5. **多级缓存**：本地缓存 + Redis 缓存
6. **异步更新**：减少主流程延迟

## 性能对比

| 方案 | 读性能 | 写性能 | 一致性 | 复杂度 |
|------|--------|--------|--------|--------|
| Cache-Aside | 高 | 中 | 最终一致 | 低 |
| Read-Through | 高 | 中 | 最终一致 | 中 |
| Write-Through | 中 | 低 | 强一致 | 中 |
| Write-Behind | 高 | 高 | 最终一致 | 高 |

## 总结

1. 优先使用 Cache-Aside 策略
2. 防止缓存穿透（缓存空值、布隆过滤器）
3. 防止缓存击穿（互斥锁、逻辑过期）
4. 防止缓存雪崩（随机过期、多级缓存）
5. 保证缓存一致性（延迟双删、监听 Binlog）
