# 分页实现经验总结

## 背景

在企业级应用中，分页是最常见的需求之一。本文总结了在实际项目中遇到的分页问题和解决方案。

## 常见问题

### 1. 深分页性能问题

**问题描述**：当页码很大时（如第 10000 页），查询速度急剧下降。

**原因**：`LIMIT 100000, 10` 需要扫描 100010 条记录，然后丢弃前 100000 条。

**解决方案**：

#### 方案一：游标分页
```sql
-- ❌ 错误：大偏移量
SELECT * FROM user ORDER BY id LIMIT 100000, 10

-- ✅ 正确：游标分页
SELECT * FROM user WHERE id > 100000 ORDER BY id LIMIT 10
```

**优点**：性能稳定，不随页码增长
**缺点**：不能跳页，只能上下翻页

#### 方案二：延迟关联
```sql
-- 先查主键
SELECT id FROM user ORDER BY id LIMIT 100000, 10

-- 再关联查询
SELECT * FROM user WHERE id IN (上面的id列表)
```

**优点**：可以跳页
**缺点**：实现复杂

### 2. 分页数据不一致

**问题描述**：翻页过程中有新数据插入，导致数据重复或遗漏。

**原因**：使用 OFFSET 分页，数据变化会导致偏移量错位。

**解决方案**：
```java
// 使用最后一条记录的 ID 作为游标
Long lastId = null;
if (lastId == null) {
    // 第一页
    return selectList("SELECT * FROM user ORDER BY id LIMIT 10");
} else {
    // 后续页
    return selectList("SELECT * FROM user WHERE id > ? ORDER BY id LIMIT 10", lastId);
}
```

### 3. 总数查询性能问题

**问题描述**：`SELECT COUNT(*)` 在大表上很慢。

**解决方案**：

#### 方案一：缓存总数
```java
// 使用 Redis 缓存总数
Long total = redisTemplate.opsForValue().get("user:count");
if (total == null) {
    total = userMapper.selectCount();
    redisTemplate.opsForValue().set("user:count", total, 1, TimeUnit.HOURS);
}
```

#### 方案二：异步更新总数
```java
// 增删操作时异步更新缓存
@Async
public void updateUserCount() {
    Long count = userMapper.selectCount();
    redisTemplate.opsForValue().set("user:count", count);
}
```

### 4. 多表联合分页

**问题描述**：多表 JOIN 后分页，性能差。

**解决方案**：
```sql
-- ❌ 错误：先 JOIN 再分页
SELECT u.*, o.*
FROM user u
LEFT JOIN order o ON u.id = o.user_id
ORDER BY u.id
LIMIT 100000, 10

-- ✅ 正确：先分页再 JOIN
SELECT u.*, o.*
FROM (
    SELECT id FROM user ORDER BY id LIMIT 100000, 10
) t
JOIN user u ON t.id = u.id
LEFT JOIN order o ON u.id = o.user_id
```

## MyBatis Plus 分页配置

### 1. 配置分页插件
```java
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```

### 2. 使用分页
```java
// 创建分页对象
Page<User> page = new Page<>(1, 10);

// 执行分页查询
Page<User> result = userMapper.selectPage(page, 
    new LambdaQueryWrapper<User>()
        .eq(User::getStatus, 1)
        .orderByDesc(User::getCreateTime)
);

// 获取结果
List<User> records = result.getRecords();
long total = result.getTotal();
```

### 3. 自定义 SQL 分页
```java
// Mapper 接口
Page<UserVO> selectUserPage(Page<UserVO> page, @Param("query") UserQuery query);

// XML 映射
<select id="selectUserPage" resultType="UserVO">
    SELECT u.id, u.username, u.email, d.name as dept_name
    FROM sys_user u
    LEFT JOIN sys_dept d ON u.dept_id = d.id
    <where>
        <if test="query.username != null and query.username != ''">
            AND u.username LIKE CONCAT('%', #{query.username}, '%')
        </if>
    </where>
    ORDER BY u.create_time DESC
</select>
```

## 最佳实践

1. **优先使用游标分页**：对于移动端、无限滚动场景
2. **缓存总数**：避免每次查询都 COUNT
3. **限制最大页码**：防止用户输入超大页码
4. **使用索引**：确保 ORDER BY 字段有索引
5. **避免 SELECT ***：只查询需要的字段

## 性能对比

| 方案 | 100 条 | 10000 条 | 100000 条 | 1000000 条 |
|------|--------|----------|-----------|------------|
| OFFSET | 1ms | 5ms | 50ms | 500ms |
| 游标分页 | 1ms | 1ms | 1ms | 1ms |
| 延迟关联 | 2ms | 3ms | 5ms | 10ms |

## 总结

1. 深分页使用游标分页
2. 总数查询使用缓存
3. 多表分页先分页再 JOIN
4. 确保 ORDER BY 字段有索引
5. 限制最大页码防止滥用
