# 数据库架构设计

## 架构概述

本项目采用 MySQL 作为主数据库，结合读写分离、分库分表等策略应对高并发场景。

## 技术选型

### 数据库
- **MySQL 8.0**: 主数据库
- **PostgreSQL + pgvector**: 向量数据库（RAG 场景）

### 中间件
- **MyBatis Plus**: ORM 框架
- **ShardingSphere**: 分库分表
- **Redis**: 缓存层

## 读写分离

### 架构
```
应用层
  ↓
ShardingSphere-JDBC
  ↓
┌─────────┬─────────┐
│  主库    │  从库    │
│  (写)    │  (读)    │
└─────────┴─────────┘
```

### 配置
```yaml
spring:
  shardingsphere:
    datasource:
      names: master,slave0,slave1
      master:
        type: com.zaxxer.hikari.HikariDataSource
        jdbc-url: jdbc:mysql://master:3306/db
        username: root
        password: root
      slave0:
        type: com.zaxxer.hikari.HikariDataSource
        jdbc-url: jdbc:mysql://slave0:3306/db
        username: root
        password: root
      slave1:
        type: com.zaxxer.hikari.HikariDataSource
        jdbc-url: jdbc:mysql://slave1:3306/db
        username: root
        password: root
    rules:
      readwrite-splitting:
        data-sources:
          ds:
            write-data-source-name: master
            read-data-source-names: slave0,slave1
            load-balancer-name: round-robin
        load-balancers:
          round-robin:
            type: ROUND_ROBIN
```

## 分库分表

### 分片策略

#### 按用户 ID 分片
```yaml
rules:
  sharding:
    tables:
      t_order:
        actual-data-nodes: ds_${0..1}.t_order_${0..15}
        database-strategy:
          standard:
            sharding-column: user_id
            sharding-algorithm-name: user-mod
        table-strategy:
          standard:
            sharding-column: order_id
            sharding-algorithm-name: order-mod
    sharding-algorithms:
      user-mod:
        type: MOD
        props:
          sharding-count: 2
      order-mod:
        type: MOD
        props:
          sharding-count: 16
```

#### 按时间分片
```yaml
rules:
  sharding:
    tables:
      t_log:
        actual-data-nodes: ds_${0..1}.t_log_${2024..2025}${01..12}
        table-strategy:
          standard:
            sharding-column: create_time
            sharding-algorithm-name: log-month
    sharding-algorithms:
      log-month:
        type: INTERVAL
        props:
          datetime-pattern: "yyyy-MM-dd"
          datetime-lower: "2024-01-01"
          datetime-upper: "2025-12-31"
          sharding-suffix-pattern: "yyyyMM"
          datetime-interval-amount: 1
          datetime-interval-unit: "MONTHS"
```

## 数据备份

### 定时备份
```bash
#!/bin/bash
# backup.sh

DATE=$(date +%Y%m%d%H%M%S)
BACKUP_DIR=/backup/mysql

# 全量备份
mysqldump -h$HOST -u$USER -p$PASS --all-databases > $BACKUP_DIR/full_$DATE.sql

# 压缩
gzip $BACKUP_DIR/full_$DATE.sql

# 清理 7 天前的备份
find $BACKUP_DIR -name "*.gz" -mtime +7 -delete
```

## 性能优化

### 索引优化
```sql
-- 创建索引
CREATE INDEX idx_user_status ON t_user(status);
CREATE INDEX idx_order_user_id ON t_order(user_id);

-- 查看索引使用情况
EXPLAIN SELECT * FROM t_user WHERE status = 1;
```

### 查询优化
```sql
-- ❌ 错误：使用函数
SELECT * FROM t_user WHERE DATE(create_time) = '2024-01-01';

-- ✅ 正确：使用范围查询
SELECT * FROM t_user 
WHERE create_time >= '2024-01-01' 
  AND create_time < '2024-01-02';
```

## 最佳实践

1. **合理分库分表**：根据业务特点选择分片键
2. **读写分离**：读多写少场景使用
3. **索引优化**：避免全表扫描
4. **连接池配置**：根据并发量调整
5. **定期备份**：防止数据丢失
6. **监控告警**：及时发现性能问题
